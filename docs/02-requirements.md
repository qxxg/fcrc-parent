# 02 · 需求规格说明

## 1. 背景

金融机构在客户准入与存续期管理中，需要把 KYC、风险评级、制裁/负面舆情筛查、人工复核、案件与监管报告串成一条可审计的链路。传统做法往往是：

- 风险与合规在各自系统里分别评估，人工汇总；
- 审批靠邮件/即时通讯，缺少状态与留痕；
- AI 工具直接读库，权限与审计边界模糊；
- 高风险客户是否放行依赖个人经验，缺少强制人工复核。

FCRC 用微服务 + 图编排 + 有权限边界的 AI Copilot 解决上述问题。

---

## 2. 角色

| 角色 | 职责 | 关键诉求 |
| --- | --- | --- |
| 客户经理 | 录入客户、发起开户 | 快速知道缺什么材料、当前卡在哪 |
| 风控专员 | 查看风险评分与因子 | 评分可解释、可复核 |
| 合规专员 | 处理筛查命中、人工复核 | 强留痕、不能漏掉高风险 |
| 合规主管 | 查看案件/报告、抽查 | 全局视图、审计可追溯 |
| 系统管理员 | 部署、监控、配置 | 一键部署、可回滚 |
| AI Copilot | 查询、分析、建议、启动流程 | 不越权、不编造、不代替人审批 |

## 3. 功能需求

### FR-01 客户管理

- 支持个人/企业客户建档；
- 字段：客户号、姓名、类型、证件号、手机号、邮箱、国家、行业、年收入、职业、PEP、渠道；
- 支持按关键字/状态分页查询；
- 支持 KYC 状态更新（PENDING / IN_REVIEW / APPROVED / REJECTED）；
- 对外响应中的证件号/手机号/姓名必须脱敏；
- 内部画像接口供工作流/风险/合规/AI 使用。

**验收**：创建客户后可通过列表与详情查询；列表不返回完整证件号；PEP 标识正确。

### FR-02 风险评分

- 输入客户画像、交易金额、交易类型、跨境、近 30 天交易笔数、新关系、高风险产品；
- 输出 0-100 分、等级、风险因子列表、建议；
- 风险因子必须可解释（代码/名称/分值/描述）；
- 评分结果持久化，支持按客户号/等级/时间查询；
- 提供统计接口。

**验收**：跨境、大额、高风险产品、新关系会提高评分；结果包含至少一个因子说明。

### FR-03 合规筛查

- 检查身份证明与受益所有人是否核验；
- 检查 PEP、负面舆情、资金来源/用途说明；
- 检查跨境与高风险国家；
- 输出 PASS / REVIEW / REJECT、风险点、发现项、建议；
- 结果持久化并可查询。

**验收**：PEP + 高风险国家 + 资金来源缺失时不得返回 PASS；发现项包含严重级别。

### FR-04 联合开户工作流

- 一次请求启动“客户加载 → 风险 + 合规并行 → 汇聚 → 自动审批/人工复核 → 收尾”；
- 自动审批条件：合规 PASS、风险分 < 40、客户非 PEP；
- 不满足条件时创建案件并暂停；
- 暂停必须持久化，服务重启后可恢复；
- 运行状态、当前节点、风险/合规结果、事件时间线可查询；
- 事件支持 SSE 实时推送；
- 提供图结构查询接口，便于教学展示。

**验收**：

1. 低风险客户自动通过并生成报告；
2. 高风险/PEP 客户进入 `WAITING_REVIEW`，生成案件；
3. 重启工作流服务后仍可复核；
4. 重复复核被拒绝；
5. 复核通过/拒绝分别走到正确收尾节点。

### FR-05 人工复核（HITL）

- 只有 `WAITING_REVIEW` 状态可复核；
- 必须提供 `decision`（APPROVED/REJECTED）、`reviewer`、`comment`；
- 复核后从 checkpoint 恢复，不允许重新跑已经完成的节点；
- 复核动作写入事件表与运行记录；
- **AI 不得调用复核接口**。

**验收**：AI 能力清单中没有复核工具；工作流复核接口要求真人身份字段；重复提交返回业务错误。

### FR-06 合规案件

- 支持创建、查询、分配、状态流转、备注；
- 案件类型：KYC_REVIEW / SANCTIONS_HIT / ADVERSE_MEDIA / TRANSACTION_MONITORING / COMPLAINT；
- 优先级：LOW/MEDIUM/HIGH/CRITICAL；
- 状态：OPEN/IN_PROGRESS/PENDING_INFO/RESOLVED/CLOSED；
- 备注只追加、不可修改；
- 支持逾期标识与统计。

**验收**：工作流转人工复核时自动创建案件；案件详情包含不可变备注时间线。

### FR-07 监管报告

- 支持客户风险报告、SAR、CTR、周期报告；
- 支持草稿 → 定稿 → 报送；
- 报送后不可修改；
- 支持 CSV 导出；
- 报告包含风险分、合规结论、因子/发现项、摘要。

**验收**：定稿后才能报送；报送后再次定稿/报送被拒绝；CSV 可下载。

### FR-08 AI Copilot

- 支持同步与 SSE 流式对话；
- 支持查询客户、风险、合规、工作流、案件、报告；
- 支持检索本地制度库并引用；
- 支持多用户/多会话隔离；
- 支持会话列表、删除、清空；
- 支持 Plan Mode 与权限模式查看/切换；
- 支持工作区文件查看；
- 支持能力清单（模型、工具、安全策略）；
- 默认 Mock 模型可在无外网/无 Key 时运行；
- 可切换 DashScope qwen。

**验收**：

1. 无 Key 时 `mock` 可完成一轮对话；
2. 同一 `(userId, sessionId)` 会话稳定；
3. 工具调用事件通过 SSE 可见；
4. `capabilities` 返回工具白名单与 HITL 说明；
5. 危险工具被拒绝。

### FR-09 驾驶舱

- 展示客户、工作流、案件、报告统计；
- 支持列表筛选；
- 支持人工复核弹窗（真人操作）；
- 支持 AI 对话与事件日志；
- 响应式布局，桌面优先。

**验收**：8080（本地）或 8088（Docker）可打开；统计与列表来自真实 API；复核后列表刷新。

## 5. 关键业务规则

### 5.1 自动审批

```text
合规 = PASS
且 风险分 < 40
且 客户.pep = false
=> AUTO_APPROVE
否则 => MANUAL_REVIEW
```

### 5.2 人工复核

- 复核人必须是真人身份（生产环境从登录态取，不能由前端伪造）；
- 复核意见必须记录；
- AI 只能建议“建议人工复核”，不能给出“已通过”；
- 复核接口不注册为 AI 工具。

### 5.3 数据保留

- 客户身份资料、交易记录、筛查记录自业务关系结束起至少 5 年；
- 报告报送后不可修改，只能追加说明；
- 案件备注不可修改，只能追加。

### 5.4 风险等级

| 分数 | 等级 | 处理 |
| --- | --- | --- |
| 0-39 | LOW | 可自动通过（仍需合规 PASS、非 PEP） |
| 40-69 | MEDIUM | 人工复核 |
| 70-89 | HIGH | 人工复核，优先处理 |
| 90-100 | CRITICAL | 人工复核，建议拒绝/上报 |

## 6. 验收矩阵

| 场景 | 输入 | 期望 |
| --- | --- | --- |
| 低风险自动通过 | 客户 1，金额 12 万，非跨境 | 合规 PASS、风险 < 40、状态 COMPLETED |
| 中风险复核 | 客户 2，金额 150 万，跨境 | 状态 WAITING_REVIEW、生成案件 |
| PEP 复核 | 客户 3（PEP） | 即使分数低也不得自动通过 |
| 高风险拒绝 | 客户 4（伊朗） | 合规不得 PASS，人工拒绝后 REJECTED |
| 重复复核 | 已复核的 runNo | 返回 ILLEGAL_STATE |
| AI 越权 | 要求 AI 审批 | AI 明确拒绝并提示真人操作 |
| 危险工具 | 要求执行 shell/写文件 | 权限拒绝，记录 ALL_TOOLS_DENIED |
| 会话隔离 | 不同 userId/sessionId | 上下文不串 |
| 报告报送 | DRAFT → FINAL → SUBMITTED | 状态合法，报送后不可改 |
| 服务重启 | WAITING_REVIEW 后重启 workflow | 仍可复核并恢复 |

## 7. 范围外

- 真实支付/账务/交易系统对接；
- 真实名单供应商与监管报送通道；
- 完整 IAM、SSO、mTLS、密钥管理；
- 移动端原生 App；
- 多租户计费；
- 模型训练/微调。
